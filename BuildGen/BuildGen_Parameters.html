BuildGen — Parameter Reference

What every control on the generator does. Listed in the same order as the node's parameter panel.

General. All sizes are in metres. Up is Y in Houdini; the same axis is called Z in Unreal. Every "Make …" toggle is off by default — the generator only builds what you switch on. Setup and the one-time block export are covered in README.txt next to this file.

Button above the tabs

Save Blocks From UEsave_from_uebutton Takes the meshes that arrived from Unreal via "Send to Houdini" and writes them into the Blocks Folder as .bgeo.sc files, with the correct names. No paths to type. It then recooks the generator, so the building appears. If you select the incoming subnet before pressing, that selection wins over the automatic search.

Floors / Blocks tab

This is where the facade is assembled. Three levels of nesting, each one a multiparm (a list with a "+" button):

Floors the storeys └ FLOOR # one storey └ Sides the sides of that storey (the faces of the building) └ SIDE #_# one side └ BLOCKS the chain of blocks along that side └ BLOCK #_#_#

Instance numbers appear in the label of the first parameter inside each entry: FLOOR #, SIDE #_#, BLOCK #_#_#. Houdini does not substitute numbers into collapsed folder headers — that is an engine limitation, not a missing feature here.

Inside a floor

ParameterDefaultWhat it does
FLOOR # — Floor Offset (Z)flooroffset#0 Manual vertical nudge for this copied floor — for blocks whose tops are stepped or uneven. Cumulative up the stack; the ground floor ignores it.
Make Copyfloorcopy#off Duplicate this floor upward as identical copies. The normal way to gain height without assembling every storey by hand.
Copiesfloorcopies#2 How many of this floor in total. 1 = just this one, no copies.
FLOOR # — Freeze Floorfrzfloor#button Locks this floor and every floor below it, copies included, so adding the next storey no longer recomputes the ones already standing. That is the difference between seconds and minutes once the building gets tall. Press it only after the floor has actually drawn in Unreal — the lock seals whatever the node is holding at that moment. See Freeze — the locks.

Freeze — Storey Stack

ParameterDefaultWhat it does
UNFREEZE STACKfrz_stack_unfreezebutton Releases the stack of finished storeys — the lock that FLOOR # — Freeze Floor puts on. Everything up to the frozen mark is recomputed once, with the current code and the current parameters. This is the way out when a storey that is already standing refuses to follow a change you made. The classic symptom: on the copied floors the stairwell door comes out too low to walk through, while the ground floor and the roof are fine — those floors were sealed by an earlier pass, and only unfreezing the stack rewrites them. Expect one long cook, minutes rather than seconds, growing with the height of the building. There is no matching FREEZE button in the panel, by design — the stack is frozen for you by FLOOR # — Freeze Floor, and a second button doing the same thing is too easy to press by accident.
Statusfrz_stack_statuslive Read-only. live means nothing is sealed; otherwise it reports how far the stack is frozen, e.g. FROZEN thru FLOOR 2 - 4 storeys, 362 prims.

Drawing the slab curve

The slab is filled from a closed contour curve, and that curve lives inside the asset. Every building has its own outline, so the asset ships without one — draw it once, after the ground floor is standing.

1 In Houdini, dive inside the generator node and draw a closed curve along the outline you want the slab to follow. 2 Connect it into the ceiling_offset node, input 0, replacing whatever was there. The slab appears immediately. 3 Press Apply Slab Curve To Type (the button works from Unreal too). 4 In Unreal, press Rebuild. 5 Switch Make Ceiling on.

Do not use Save Node Type for this. That command writes the contents of the node you are standing on back into the asset, and a working node is not an exact copy of it — anything the node happens to be missing at that moment is dropped from the asset. Apply Slab Curve To Type avoids this: it copies the curve into a fresh instance, compares the node list before and after, and restores the backup if anything would go missing. Steps 3 and 4 can be repeated as often as you like; each press leaves a timestamped .hda backup next to the asset.

Freeze — the locks

A tall building is expensive to rebuild: every change makes Houdini recompute the storeys and makes Unreal reassemble the meshes, and that reassembly alone is the single largest cost in the whole loop. The freeze controls exist to stop paying it for parts that are already finished.

Each group is the same three controls — FREEZE …, UNFREEZE … and a read-only Status — and they sit next to the stage they belong to. The storey stack is the one exception — it is frozen for you, so only its UNFREEZE is in the panel:

Floors / Blocks tab Freeze — Blocks the assembled facade Freeze — Floor / Ceiling the slabs Freeze — Whole Storey the finished storey, all parts merged FLOOR # — Freeze Floor this floor and everything below it UNFREEZE STACK releases what Freeze Floor sealed Stairs / Elevator tab Freeze — Stairs / Elevator the stairs, both shafts and the car Columns tab Freeze — Columns the column grid

A lock seals the geometry at that stage and takes it out of the recompute. Status reads live while the stage is still being computed, and reports what was sealed once it is frozen.

The one rule worth remembering: a lock stores finished geometry, not the recipe. If you change the asset, a parameter or a block after freezing, the frozen parts keep their old shape and will not pick the change up — they are a snapshot, not a live branch. When something refuses to follow a change you just made, the answer is almost always to unfreeze that stage, let it cook once, and freeze it again.

The storey stack is the one lock with no FREEZE button. FLOOR # — Freeze Floor is what seals it; UNFREEZE STACK, in its own group next to the floors, is what lets it go. Reach for it whenever a storey that is already standing ignores a change — a low stairwell door on the copied floors is the usual way this shows up. It costs one long cook, but a single unfreeze is far cheaper than releasing three other stages one at a time to chase the same symptom.

Order matters in one place. Freeze the columns only after the stairs and shafts exist. Columns that would stand inside a shaft are culled automatically, but a lock pressed too early seals the grid as it was — complete with a column standing in the stairwell.

Two smaller habits that save a rebuild: set the collision Wall Thickness before FREEZE BLOCKS, and leave the roof unfrozen — it is one level, it costs little, and it is the part you keep adjusting.

Roof tab

ParameterDefaultWhat it does
Make Roofmakeroofoff The top level. There are no columns and no ceiling slab up here (the storey below already built it), while the facade, the stairs and both shafts are built as usual. Its height comes from the blocks you put on it — a parapet is routinely about two metres — and the stair and lift housings that stand on the roof get their own floor of 4 m, so the 2.74 m shaft door and its lintel still fit inside a hut rather than a tower.
Sides → ROOF SIDE # — Corner World Sourcecornersrc900_#— Corner mesh of a roof side. Works like the sides of a storey, but without bends and transforms — the shape is taken from the building outline.
BLOCKS → ROOF BLOCK #_# — World Sourceblksrc900_#_#— Blocks along a roof side — usually the parapet.

Filling the roof slots. Make Roof fills the roof sides for you by copying the recipe of the ground floor, so the slots start out holding ground-floor blocks — tall ones. Replace them with the parapet blocks before judging the result. Assign a roof block only while its source node is actually alive and drawn; a slot filled from a node that is not there gets stuck showing whatever stood before, and reassigning on top of it does not clear it.

Unreal tab

ParameterDefaultWhat it does
Blocks Folderblocksdir$HIP/geo The folder the building blocks are read from. In Houdini, leave it alone — $HIP/geo is the "geo" folder next to the scene file, and Save Blocks From UE writes exactly there, so the two can never drift apart. In Unreal, $HIP points at a temporary session folder, so type the absolute path of your own geo folder here once, for example D:/BuildGen/geo.

Pack tab

ParameterDefaultWhat it does
Make Instant Static Meshismstateon Packs identical blocks into Instanced Static Meshes: in Unreal you get one ISM per unique mesh instead of a separate static mesh per block. Geometry, transforms and collision are unchanged — only the number of assets the bake produces. On by default; there is rarely a reason to turn it off.

Collision tab

UCX groups are written inside the packed geometry, so every instance carries its own collision. Instances get no collision any other way.

ParameterDefaultWhat it does
Collision ModeucxmodeUCX From Block Silhouette Off — no collision. UCX From Block Silhouette — collision follows the outline of the block, so openings stay open. Single Box Per Mesh — one box per mesh: cheap and crude.
Cell Sizeucxcell0.25 Grid step used to read the silhouette. Smaller means collision hugs windows and doors more tightly, at the cost of more hulls.
Wall Thicknessucxthick0.3 How far the collision reaches back from the outer face. Blocks often carry a fake interior 1.2 m deep — collision must not follow it, or the rooms lose that much floor space. Set this before freezing the blocks.
WindowsucxglassmodeAuto Detect Panes Windows stay solid in every mode. Merged Into Walls — the glass is simply part of the wall. Auto Detect Panes — each pane gets its own convex hull, so it can be removed later when the glass breaks. By Material Name — panes are found by material name instead.
Window Material Nameucxglasstokglass Space separated substrings, matched against unreal_material, case-insensitive. Used only in By Material Name mode.

About the UV parameters

Almost every generated part — floor slab, ceiling top and bottom, stairs, shafts, elevator and its car — carries the same set of four parameters. They are an ordinary Houdini UV projection:

UV TypeFace Projection method. The default Face unwraps each face on its own, which is what slabs and walls want. The other entries (Orthographic, Cylindrical, Rows & Columns and so on) are the standard UV Project list.
UV Scale0.3 Texture scale. Smaller numbers stretch the texture larger.
UV Angle0Rotates the projection.
UV Offset0 0 0Shifts the projection.
